# T1.5 样品检测主链

T1.5 完成真实 API 主链：样品登记 -> 检测任务分配 -> 结果草稿/提交 -> 审核通过或退回。

T1.5 样品、检测方法、检测任务和检测结果页面始终调用真实 API；Mock 数据库和 Mock server 不再提供这些实体。

## 角色映射

| 现有角色 | T1.5 能力 |
|---|---|
| `admin` | 全局样品、方法、任务和结果管理；全局审核 |
| `project_manager` | 负责项目内样品管理、任务分配、结果审核 |
| `operator` | researcher/analyst 执行者；仅执行分配给自己的任务并录入、提交结果 |
| `director` | T1.5 viewer；全局只读 |

演示账号 `analyst` 的规范角色值仍为 `operator`，用于浏览器验收分析员流程。

## 状态机

- 样品：`registered -> in_testing -> pending_review -> completed`，管理者可置为 `cancelled`。
- 检测任务：`pending -> in_progress -> completed`；`pending/in_progress -> cancelled`。`completed` 仅由结果审核通过触发。
- 检测结果：`draft -> submitted -> approved/rejected`；`rejected` 编辑后回到 `draft`，可再次提交。

## API

- `/api/samples`：列表、新建；`/{id}` 详情、编辑、软删除；`/{id}/status` 状态变更。
- `/api/test-methods`：列表、新建；`/{id}` 详情、编辑；`/{id}/activation` 启停。
- `/api/test-tasks`：列表、新建；`/{id}` 详情；`/{id}/assignee` 分配；`/{id}/status` 合法流转。
- `/api/test-results`：列表、新建草稿；`/{id}` 详情、编辑；`/{id}/submit|approve|reject` 提交与审核。

## 数据库迁移

`202606250002_complete_t1_5_lims_main_chain.py` 保留既有物理表名 `sample_test` 和 `result`，扩展其 TestTask/TestResult 语义，避免高风险改名：

- `sample`：增加 `amount`、`unit`、`storage_condition`。
- `test_method`：增加 `category`、`version`、`description`。
- `sample_test`：增加 `priority`、`due_date` 及状态/负责人索引。
- `result`：增加 `result_data`、`conclusion`、`status`、`submitted_by`、`submitted_at` 及状态索引。

## 浏览器验收

1. 以 `project_manager / password123` 登录，新建样品并分配给 `analyst`。
2. 以 `analyst / password123` 登录，进入样品详情，开始任务、保存结果草稿并提交。
3. 以 `project_manager` 登录 `/testing`，退回并填写原因。
4. 以 `analyst` 修改退回结果并重新提交。
5. 以 `project_manager` 审核通过；确认结果、任务、样品分别为 `approved`、`completed`、`completed`。
