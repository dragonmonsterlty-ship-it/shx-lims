# T1.5.1 稳定性检查与回归报告

日期：2026-06-25

基线提交：`58ff6f9d1aeb0e69346f97db9f57668dd78aba4f`

## 结论

T1.5 主链可在独立 PostgreSQL 空库中从零迁移、重复 seed，并通过后端、前端、全栈和真实 API 回归。

本轮发现并修复三类稳定性问题：

1. T1.5 前端 service、Mock 数据库和 Mock server 仍保留样品/任务/方法/结果的 Mock 分支与数据。
2. 真实 API smoke 只覆盖提交后通过，未覆盖退回、修改、再次提交。
3. T1.5 OpenAPI 响应被描述为无结构 `object`，无法暴露响应 DTO 字段。

## 修复内容

- T1.5 样品与结果 service 固定使用真实 API。
- 删除 T1.5 主链 Mock fixture 和 handler，并增加防回退测试。
- 真实 API smoke 扩展为：
  `draft -> submitted -> rejected -> draft -> submitted -> approved`。
- 增加关闭状态回归：已通过结果不可再编辑，已完成任务不可倒退或取消。
- 为 T1.5 路由增加泛型 `ApiResponse[T]` OpenAPI 响应模型，并验证关键响应字段。

## 契约对齐

- `/api/samples`：列表、详情、新建、编辑、状态、软删除路径与前端一致。
- `/api/test-methods`：列表、详情、新建、编辑、启停路径与字段一致。
- `/api/test-tasks`：创建、筛选、分配、状态路径与字段一致。
- `/api/test-results`：草稿、修改、提交、通过、退回、列表和详情路径与字段一致。
- 状态枚举一致：
  - Task：`pending | in_progress | completed | cancelled`
  - Result：`draft | submitted | approved | rejected`
- OpenAPI 现在暴露 `SampleRead/Page`、`TestMethodRead/Page`、`TestTaskRead/Page`、`TestResultRead/Page`。
- 前端错误继续由统一 request/error 层上抛；T1.5 service 未静默吞掉写操作错误。

## 权限与行级安全

自动化测试覆盖：

- operator 仅能查看和执行分配给自己的任务。
- operator 不能审核结果。
- director 可全局只读，不能创建任务、修改状态或审核。
- project_manager 只能管理负责项目。
- 跨项目 sample/task/result 直接访问和写入失败。
- rejected 结果编辑后回到 draft，可再次提交。
- approved 结果不能被 operator 修改。
- completed 任务不能倒退或取消。

## T1.6 接入前风险（仅记录，不实现）

- 稳定 ID：Sample、SampleTest、Result、ExperimentRecord、DailyReport 均有稳定主键。
- 项目追溯：
  - Sample 直接包含 `project_id`。
  - TestTask 通过 Sample 追溯项目。
  - TestResult 通过 TestTask -> Sample 追溯项目。
  - ExperimentRecord 直接包含 `project_id`。
  - DailyReportItem 包含 `project_id`，日报可包含多个项目。
- 操作人字段：主链具备 `created_by/updated_by/submitted_by/reviewed_by` 等必要字段。
- 权限复用风险：testing service 的项目查看/管理判断目前为模块内函数；后续附件模块应复用统一的实体到项目解析和 capability，而不是复制判断。
- 命名风险：物理模型/表为 `SampleTest/sample_test`、`Result/result`，公共 DTO/API 为 `TestTask/test-tasks`、`TestResult/test-results`。目前不是运行时 bug，但附件统一绑定前应明确稳定的公共 entity type。

## SQLite 技术债

- fresh SQLite migration：通过。
- fresh SQLite seed：仍失败于
  `sqlite3.IntegrityError: NOT NULL constraint failed: experiment_record.id`。
- 根因仍是既有 BigInteger 主键在 SQLite 下不具备 PostgreSQL 等价的自增语义。
- PostgreSQL migration/seed、当前 pytest 和 `verify-fullstack.ps1` 不受影响。
- 按 T1.5.1 边界仅记录，不重构主数据模型。
