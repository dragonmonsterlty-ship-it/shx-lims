# T1.6A_ATTACHMENTS

本文档说明 T1.6A「真实附件闭环」的公共契约、权限、存储和限制。T1.6A 只覆盖真实附件上传、列表、下载、软删除闭环；不包含审计系统、时间线、对象存储接入或 T1.6B 扩展。

## 附件实体契约

公共附件只允许绑定以下 `entity_type`：

- `experiment`
- `daily_report`
- `sample`
- `test_task`
- `test_result`

统一 DTO 字段：

- `id`
- `entity_type`
- `entity_id`
- `project_id`
- `original_filename`
- `storage_key`
- `content_type`
- `file_size`
- `checksum_sha256`
- `storage_backend`
- `uploaded_by`
- `uploaded_at`
- `deleted_at`

核心约束：

- `entity_type + entity_id` 必须能解析到业务对象和唯一 `project_id`。
- `attachment.project_id` 必填，并且下载、详情、删除时会重新解析业务对象并校验项目一致性。
- 删除为软删除：写入 `deleted_at`，不物理删除本地文件。
- 下载由后端受控返回，不暴露服务器真实路径。
- OpenAPI JSON 响应使用明确 DTO：`AttachmentRead`、`AttachmentDeleteResult` 及其 `ApiResponse` 包装。

## entity_type 与内部模型映射

| 公共 entity_type | 内部模型 | 说明 |
| --- | --- | --- |
| `experiment` | `ExperimentRecord` / `experiment_record` | 对外不暴露内部表名。 |
| `daily_report` | `DailyReport` / `daily_report` | 上传附件要求日报恰好关联一个项目。 |
| `sample` | `Sample` / `sample` | 沿用 T1.5 样品项目权限。 |
| `test_task` | `SampleTest` / `sample_test` | 公共 API 使用 `test_task`，不暴露内部 `sample_test` 命名。 |
| `test_result` | `Result` / `result` | 公共 API 使用 `test_result`，不暴露内部 `result` 命名风险。 |

Daily report 附件特殊规则：

1. 关联恰好 1 个 project：允许上传，`attachment.project_id` 取该项目。
2. 关联 0 个 project：拒绝上传，返回 400。
3. 关联多个 project：拒绝上传，返回 400。

错误信息：

`Daily report attachments require exactly one linked project.`

这只限制 `daily_report` 附件上传。日报本身仍可支持零项目或多项目。

## API 列表

所有路径以 `/api` 为前缀：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/attachments` | multipart 上传，表单字段：`entity_type`、`entity_id`、`file`。 |
| `GET` | `/attachments?entity_type=&entity_id=` | 按公共实体类型和业务对象 ID 列表。 |
| `GET` | `/attachments/{id}` | 获取附件元数据。 |
| `GET` | `/attachments/{id}/download` | 后端受控下载，返回文件 bytes。 |
| `DELETE` | `/attachments/{id}` | 软删除附件。 |

下载响应头：

- `Content-Disposition: attachment; filename*=UTF-8''...`
- `X-Content-Type-Options: nosniff`

## 权限矩阵

| 角色 | 上传 | 列表/详情 | 下载 | 删除 |
| --- | --- | --- | --- | --- |
| `admin` | 全局允许 | 全局允许 | 全局允许 | 全局允许 |
| `project_manager` | 仅自己管理的项目对象 | 仅自己管理的项目对象 | 仅自己管理的项目对象 | 仅自己管理的项目对象 |
| `operator` | 仅自己有权限且对象可编辑 | 仅自己有权限的对象 | 仅自己有权限的对象 | 仅自己上传且对象仍允许编辑 |
| `director` | 不允许 | 只读允许 | 只读允许 | 不允许 |

对象权限来源：

- `sample`、`test_task`、`test_result` 沿用 T1.5 项目、任务分配和结果编辑权限。
- `experiment` 沿用实验记录查看/编辑权限。
- `daily_report` 沿用日报查看权限；上传和删除还要求恰好一个项目并满足角色规则。
- 跨项目 `entity_id` 或 `attachment_id` 会被 resolver 和 `attachment.project_id` 一致性校验拒绝。
- 不能通过伪造 `entity_type/entity_id` 越权访问附件。

## 文件大小/类型限制

默认限制：

- 单文件最大 20 MB。
- 允许扩展名：`jpg,jpeg,png,pdf,txt,csv,xlsx,xls,docx,doc`。
- 禁止扩展名：`exe,bat,cmd,ps1,sh,js,mjs,cjs,html,htm`。
- 禁止 MIME：`application/x-msdownload`、`application/x-executable`、`application/x-sh`、`text/x-shellscript`、`text/html`、`application/javascript`、`text/javascript`。

后端安全校验：

- 拒绝 `../`、绝对路径、Windows drive/path 分隔符和控制字符文件名。
- 不只信任前端 MIME；后端会基于内容做 PDF/PNG/JPEG/ZIP/HTML/文本基础识别。
- HTML 或脚本内容即使伪装为 `.txt` 也会被拒绝。
- 同名文件不会覆盖；本地 storage key 使用 opaque UUID 路径。
- 删除后详情和下载返回 404。

## 本地存储配置

配置项：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `ATTACHMENT_STORAGE_ROOT` | `storage/attachments` | 本地附件根目录。 |
| `ATTACHMENT_STORAGE_BACKEND` | `local` | T1.6A 仅支持 `local`。 |
| `ATTACHMENT_MAX_SIZE_BYTES` | `20971520` | 默认 20 MB。 |
| `ATTACHMENT_ALLOWED_EXTENSIONS` | `jpg,jpeg,png,pdf,txt,csv,xlsx,xls,docx,doc` | 允许扩展名。 |
| `ATTACHMENT_BLOCKED_EXTENSIONS` | `exe,bat,cmd,ps1,sh,js,mjs,cjs,html,htm` | 禁止扩展名。 |
| `ATTACHMENT_BLOCKED_MIME_TYPES` | 见配置默认值 | 禁止 MIME。 |

本地存储行为：

- 只返回相对 `storage_key`，不返回真实服务器路径。
- 保存路径为 `<uuid-prefix>/<uuid><suffix>`。
- 读取和删除都会解析并确认 key 位于配置根目录内，防止路径穿越。

## 对象存储预留点

后端定义 `AttachmentStorage` 协议：

- `save(content, suffix) -> storage_key`
- `read(storage_key) -> bytes`
- `exists(storage_key) -> bool`
- `delete(storage_key) -> None`

T1.6A 只实现 `LocalAttachmentStorage`。S3、MinIO、OSS 等对象存储不在本轮接入；未来可在该协议后增加实现，并保持 API/DTO 不变。

## 已知限制和技术债

- T1.6A 不做审计日志、时间线聚合或附件操作记录。
- T1.6A 不做秒传、分片上传、病毒扫描、在线预览或缩略图。
- T1.6A 删除为软删除，默认不物理清理本地文件；后续可设计后台清理策略。
- `daily_report` 多项目附件暂不支持；若后续需要，应设计 item-level 附件或 user-level 附件，不在 T1.6A 处理。
- 旧 `ExperimentAttachment` / `DailyReportAttachment` 元数据仍可能存在于历史模型中，但 T1.6A 前端真实附件闭环只使用统一 `/attachments` API。
- 公共 `test_task` 映射内部 `SampleTest`，公共 `test_result` 映射内部 `Result`；不要在外部 API、前端类型或文档中暴露内部表名作为实体类型。
