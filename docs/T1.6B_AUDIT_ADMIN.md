# T1.6B Audit and Admin Backend

## Scope

T1.6B adds the backend-only audit and admin-management minimum loop. It does not add frontend pages, object storage, inventory enhancements, scanning, AI, search, or reporting.

Baseline: T1.6A attachment commit `9afef2eb38b8b8afb82733a0294a48a876c853a6`.

## Model and Migration

Migration: `backend/alembic/versions/202606260001_add_t1_6b_audit_admin.py`

`audit_log` is rebuilt into the unified T1.6B shape:

- `id`
- `actor_user_id`
- `actor_role`
- `action`
- `entity_type`
- `entity_id`

## Stable Values

Actions:

- `create`
- `update`
- `delete`
- `submit`
- `approve`
- `reject`
- `archive`
- `upload`
- `download`
- `enable_user`
- `disable_user`
- `change_role`
- `reset_password`

Entity types:

- `experiment`
- `daily_report`
- `sample`
- `test_task`
- `test_result`
- `attachment`
- `user`

Task assign/start/complete/cancel are recorded as `action="update"` with `metadata.task_event` set to `assign`, `start`, `complete`, or `cancel`, keeping the action vocabulary stable.

- `GET /api/admin/users`

## Permission Matrix

| Actor | Audit list | Entity timeline | Admin users |
| --- | --- | --- | --- |
| admin | All logs | All accessible entities | List, enable/disable, change role, reset password |
| project_manager | Managed project logs only | Existing entity permissions | Forbidden |
| operator/researcher/member | Forbidden | Existing entity permissions only | Forbidden |
| viewer | Forbidden | Read-only existing entity permissions only | Forbidden |
| cross-project user | Hidden/denied | Hidden/denied | Forbidden unless admin |

User management guards:

- Admin cannot disable self.
- Admin cannot remove own admin role.
- Last active admin cannot be disabled or demoted.
- Password reset sets `must_change_password=true`.

## Risks

- Existing audit rows from the older generic `audit_log` shape are dropped by the migration because the old columns do not map cleanly to T1.6B's entity/action model.
- Task assign/start/complete/cancel are stored as stable `update` actions with `metadata.task_event`; consumers must inspect metadata for those finer task events.
- No frontend audit or admin UI is included in this milestone.
